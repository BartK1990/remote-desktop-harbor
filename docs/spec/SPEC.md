# Remote Desktop Harbor — Product Specification

| | |
|---|---|
| Status | Accepted (v0.1) |
| Platform | Windows 10 1809+ / Windows 11, x64 |
| Decisions | [ADR index](../adr/README.md) |

## 1. Purpose

A fast Windows desktop app that keeps a catalog of Remote Desktop connections with their credentials,
opens them in the regular Windows Remote Desktop client with one click, and — when a team shares a database —
shows who is currently connected to which machine.

## 2. Users and context

* IT admins / engineers who connect to many Windows servers.
* Standard (non-admin) Windows accounts, domain-joined, Entra-joined or local.
* Either working alone (local vault) or as a team sharing one SQL database.

## 3. Functional requirements

### 3.1 Catalog

| ID | Requirement |
|---|---|
| FR-01 | The app stores entries with: name, folder, host, port, domain, user name, password, notes, additional accounts (FR-09), and (for RDP entries) additional `.rdp` settings. |
| FR-02 | Users can create, edit, delete and search entries (by name, host, user, folder, notes). Entries are shown in a compact folder tree: one low row per folder or entry with an icon (folder, RDP connection, credentials only, other) and its name; entry rows also show the host on the right in a monospace font, with the port when it is not 3389 (or the in-use marker, FR-33); rows keep a right gutter so the scroll bar never covers the host or the in-use marker. Folders can be nested (`Production/Web`; `/` or `\` separates levels) and each can be expanded and collapsed; collapsed folders are remembered across restarts. The search filters the tree as you type and expands every folder with matches. See [ADR-0017](../adr/0017-compact-folder-tree.md), [ADR-0025](../adr/0025-theme-tokens.md). |
| FR-55 | The **size of the entry list** rows can be changed from 80 % to 160 % in 10 % steps: the **−** and **+** buttons above the tree, <kbd>Ctrl</kbd>+<kbd>Plus</kbd> / <kbd>Ctrl</kbd>+<kbd>Minus</kbd>, or <kbd>Ctrl</kbd>+mouse wheel over the tree. Icons, text, row height and indent scale together; the scroll bar does not. The current size is shown between the buttons; clicking it, or <kbd>Ctrl</kbd>+<kbd>0</kbd>, goes back to the default 100 %. The size is personal and remembered across restarts. See [ADR-0034](../adr/0034-entry-list-zoom.md). |
| FR-56 | The **width of the entry list pane** is set by dragging the divider between the list and the details pane, and is remembered across restarts as the list's share of the two panes, so it fits the window at any size; the panes' minimum widths still apply. Double-clicking the divider restores the default split (2 : 3). The width is personal. See [ADR-0026](../adr/0026-main-window-layout.md). |
| FR-62 | **Smart groups**, like those of Remote Desktop Connection Manager: virtual groups in the entry tree that hold no entries of their own but list every entry their rules match, kept up to date as entries change. A smart group has a name, an optional folder — it is shown there, before the sub-folders, and only considers entries in that folder and below; without one it is shown at the top of the tree and considers every entry — **all rules** or **any rule**, and rules of *field* (name, host, folder, user name of any account, notes, environment tag FR-49, kind FR-03), *comparison* (contains, does not contain, is, is not, starts with, ends with, matches / does not match a regular expression; case is ignored; an empty value with *is* / *is not* means an empty field) and *value*. A group without rules lists its whole folder; an invalid regular expression never matches and blocks saving. Its row shows a filter icon, the name in italics and the number of entries, with the rules as tooltip. Listed entries are references: selecting one selects the entry (details pane, Connect, copy, pin, edit, delete) and the entry keeps its row in its folder. The search and the filters (FR-50) apply inside smart groups; while searching, groups without matches are hidden, and a group whose folder has no visible entries is shown at the top level only while nothing is filtered. Groups are created, edited and deleted from the tree context menu (**New smart group…** in the selected folder, **Edit smart group…**, **Delete smart group**, the last asking first and never deleting entries) or with F2 / Del on the group; the editor shows how many entries match while typing. Expansion is remembered. Smart groups are personal: kept in the user's settings (`SmartGroups`, `CollapsedSmartGroups`), never in a shared database. See [ADR-0040](../adr/0040-smart-groups.md). |
| FR-03 | Each entry is one of three kinds: **RDP connection** — a full Remote Desktop profile (host + `.rdp` settings) with optional credentials; **Credentials only** — just user name/password and an optional host; launching uses default RDP settings; **Other** — credentials, optional host and port of a system not reached with Remote Desktop (VNC, web portal, VPN…): it is never launched (Connect is disabled), its credentials and host can be copied. See [ADR-0033](../adr/0033-other-entry-kind.md). |
| FR-04 | Passwords are encrypted by the app before they are written to any database and are decrypted only at the moment of use (launch, copy). |
| FR-05 | Existing `.rdp` files can be imported. Host, port, domain and user become fields; other settings are kept; any saved password in the file is discarded. |
| FR-54 | Entries can be imported from a **Remote Desktop Manager** CSV export (toolbar **Import RDM…**). Columns are found by name. *RDP (Microsoft Remote Desktop)* rows become RDP connections, *Username and password* rows credentials-only entries and every other type (VNC, TeamViewer, Website, Citrix, VPN, KeePass…) **Other** entries (FR-03) whose notes start with `Type: <RDM type (subtype)>` and the `URL`: Name, Group (folder path, `\` separated), Host (`host:port` split), Port, CredentialDomain, CredentialUserName (`DOMAIN\user` split), CredentialPassword (encrypted on save, FR-04), Description and Keywords (notes) and OpenInConsole (`administrative session:i:1`); web credentials (`DataEntry.Web*`) fill an entry without credentials or else become an additional account (FR-09). Folder rows are skipped (folders come from Group). Before anything is saved one confirmation lists how many entries are added, how many already exist (same kind, name, folder, host, port and user — left out, so a second import adds nothing) and how many folder rows are skipped, and reminds that the CSV holds plain-text passwords; its **Import** button needs a click, Cancel is the default (FR-53). Comma or semicolon separators and quoted multi-line fields are accepted. See [ADR-0032](../adr/0032-import-remote-desktop-manager-csv.md). |
| FR-06 | Users can copy the user name, the password and the host (`host`, or `host:port` for a non-default port) to the clipboard. A copied password is cleared from the clipboard after 30 s if unchanged. |
| FR-07 | The app shows its release version (e.g. `0.1.0`) in the main window title and in Settings → About, together with the build commit when known. The version comes from the release build (`-p:Version`), so the app and its GitHub release always match. |
| FR-08 | The user can choose the colour theme — **System** (follow the Windows light/dark setting, default), **Light** or **Dark** — in **Settings → Appearance**. The theme previews as soon as it is picked; **Save** keeps it without a restart (and without the restart prompt when nothing else changed), **Cancel** goes back to the saved theme. The choice is remembered across restarts. The colours the app adds to the theme (in use, online, offline, errors) have a light and a dark variant that follow the theme, including a Windows light/dark switch while **System** is chosen; views use no fixed colours. Host, port and user names are shown in a monospace font. See [ADR-0025](../adr/0025-theme-tokens.md), [ADR-0027](../adr/0027-side-navigation-dialogs.md). |
| FR-09 | An entry can have **several accounts**, for hosts that allow several sessions at once (e.g. Windows Server): the entry's own domain/user name/password is its default account, followed by any number of additional accounts (user name, optional domain — empty uses the entry's — and password). In the tree an entry with additional accounts can be expanded to one row per account (default first). Connecting and copying the user name or password use the selected account row, or the default account when the entry row is selected. Each account's password is encrypted on its own and bound to that account (FR-04, NFR-11). Search also matches account user names. See [ADR-0019](../adr/0019-multiple-accounts-per-entry.md). |
| FR-47 | The main window is built for keyboard use. **Title bar** (FR-52): the Quick connect field (FR-48) and the signed-in user. **Toolbar:** search box with a placeholder and its shortcut, icon buttons for New, Import .rdp…, Import RDM… (FR-54) and Refresh, and a Settings button (the theme is chosen in Settings, FR-08). **Details pane** of the selected entry: folder and kind, name, host; **Connect as &lt;account&gt;** naming the account it uses, with a menu of the entry's accounts (FR-09); Copy password, Copy user, Edit and a More menu (Copy host, Delete); an active-sessions table (user, account, machine, since) that says whether connecting with the selected account takes a session over (FR-33); cards for the connection (host, port, user, password, each with a copy button), a summary of the RDP settings (RDP connections) and the notes; the last change and the entry version. **Status bar:** last status, number of entries in use, storage state with an online/offline dot. **Shortcuts**, shown next to their actions or in their tooltips: Ctrl+K quick connect (FR-48), Ctrl+F search, Ctrl+D pin (FR-50), Ctrl+N new, F2 edit, Del (in the tree) delete (both also act on a selected smart group, FR-62), Ctrl+Shift+C / U / H copy password / user / host, Ctrl+, settings, F5 refresh, Ctrl+Shift+T transfer files (FR-60), Ctrl+Plus / Ctrl+Minus / Ctrl+0 entry list size (FR-55). See [ADR-0026](../adr/0026-main-window-layout.md). |
| FR-48 | **Quick connect** (Ctrl+K, or the toolbar button) opens a palette over the main window: a query box and up to 12 results, one per entry and one per additional account (FR-09), each with name, host, user, folder, environment tag (FR-49), pin star and in-use marker (FR-33); results keep a right gutter so the scroll bar never covers the in-use marker. Every word of the query must match the name, host, user or folder; name matches rank first (exact, prefix, word start, anywhere), then host, user and folder; pinned and recent entries (FR-50) come first among equals, and an empty query lists them. Up/Down pick a result, Enter or a double-click selects it in the tree and connects with its account, Shift+Enter only selects it, Ctrl+Shift+C / U / H copy its password / user / host and F2 edits it (each selects it and closes the palette), Esc or a click outside closes the palette. See [ADR-0028](../adr/0028-quick-connect-tags-pins.md). |
| FR-49 | **Environment tags** are derived from folder names: a folder level whose name contains a whole word *prod/production/prd/live*, *staging/stage/stg/preprod/uat*, *test/testing/tst/qa*, *dev/development* or *lab/sandbox* is tagged **PROD**, **STG**, **TEST**, **DEV** or **LAB**. The folder row shows its own tag; an entry takes the tag of the outermost tagged folder above it and shows it in the details pane and in quick connect. Tags have their own light and dark colours and always show their text. No configuration or schema change. See [ADR-0028](../adr/0028-quick-connect-tags-pins.md). |
| FR-50 | Users can **pin** entries (star in the details pane, context menu, Ctrl+D); pinned entries show a star in the tree. The app remembers the last 10 entries the user connected to. Filters above the tree show **All**, **In use**, **Pinned** or **Recent** entries, combined with the search. Pins and recent entries are personal: kept in the user's settings (`PinnedEntryIds`, `RecentEntryIds`), never in a shared database. See [ADR-0028](../adr/0028-quick-connect-tags-pins.md). |
| FR-51 | Connecting to an entry tagged **PROD** (FR-49) asks for confirmation first, naming the entry, its folder and the account. When the connection would also take over a session (FR-33) the takeover question mentions production instead, so at most one question is asked. Settings → Remote Desktop can turn the production question off (`ConfirmProductionConnect`, default on). See [ADR-0029](../adr/0029-app-title-bar.md). |
| FR-52 | Every window draws the app's own **title bar**, 32 px high, in the app's theme: icon, title (dimmed while the window is inactive), optional content and caption buttons drawn like the system's (Minimize, Maximize/Restore, Close; dialogs show Close only; Close turns red on hover). The main window puts the Quick connect field (FR-48) in the middle and the signed-in user on the right. Dragging, double-click to maximize, Aero snap, the Windows 11 snap layouts on hovering Maximize, resizing from every edge, the window shadow and the system menu (Alt+Space, right-click) keep working; a maximized window keeps its content on screen. See [ADR-0029](../adr/0029-app-title-bar.md). |
| FR-53 | Confirmations and errors use the app's own **message box** (title bar of FR-52, theme tokens, an icon by kind, selectable message text) instead of the system one. Buttons name the action ("Delete", "Connect anyway", "Close anyway"). For a confirmation whose "yes" has consequences — deleting an entry, taking over a session (FR-33), connecting to production (FR-51), closing with sessions open (FR-34) — **Cancel is the default**: Enter and Esc cancel, the action needs a click, Tab + Space, or Tab + Enter; the highlighted (accent) button is always the one Enter chooses. See [ADR-0030](../adr/0030-app-message-box.md). |

### 3.2 Launching Remote Desktop

| ID | Requirement |
|---|---|
| FR-10 | Activating an entry (button, double-click, Enter) opens the standard Windows Remote Desktop client (`mstsc.exe`) as its own window — not embedded in the app — already connected with the stored credentials. File transfers may connect in Harbor's own transfer window instead (FR-65). |
| FR-11 | The password is handed to the client through Windows Credential Manager (`TERMSRV/<host>`), never via command line or `.rdp` file. It is stored as a generic credential, which Remote Desktop accepts even where Windows Defender Credential Guard blocks saved domain credentials ([ADR-0035](../adr/0035-generic-termsrv-credential.md)). By default the credential is removed shortly after launch and never survives logoff; a setting can keep it. Accounts of one host share that credential: a launch's cleanup never removes a credential written by a later launch, and launching an account without a stored password first removes a credential the app wrote moments before for another account (FR-09). |
| FR-12 | Temporary `.rdp` files are deleted after launch; leftovers from crashes are removed at next start. |
| FR-13 | The entry editor shows the common `.rdp` settings of an RDP connection as form fields instead of raw text: display mode (full screen / window), resolution (match local screen, common presets or a custom width × height of 200–8192 px), colour depth, all monitors, dynamic resolution, smart sizing; remote audio, microphone, Windows key combinations, clipboard, printers, smart cards, all local drives; server authentication, automatic reconnect, administrative session. Only values that differ from the launch defaults are stored. Any other line — unknown keys or values the form cannot show — is kept verbatim in an "Other .rdp settings" box. The stored format stays `.rdp` text (no schema change). See [ADR-0022](../adr/0022-rdp-settings-form.md). |

### 3.3 Storage

| ID | Requirement |
|---|---|
| FR-20 | **Local mode:** all data lives in a SQLite file in the user's profile (or next to the exe in portable mode). |
| FR-21 | **Remote mode:** all entries *including encrypted passwords* live in a shared SQL database (SQL Server / Azure SQL in v1). The design must allow adding other SQL engines without changing business logic. |
| FR-22 | In remote mode every client keeps a local SQLite copy of the shared data (still encrypted). When the shared database is unreachable, the app starts from and works with this copy: browse, search, copy, launch. Edits are disabled while offline and the UI says so. |
| FR-23 | The local copy is refreshed incrementally at start, periodically (default 60 s), on demand (F5), and after each own change. Deletions propagate. |
| FR-24 | Concurrent edits are detected (optimistic concurrency); a stale edit is rejected with a message, never silently overwrites. |
| FR-25 | The remote schema can be created/upgraded automatically by the app (optional; needs DDL rights) and is versioned. |
| FR-26 | The Settings dialog always opens showing the saved configuration (storage mode, key protection, sign-in). Choosing an option in one section never changes another section. |
| FR-28 | The shared vault key can be protected by **database sign-in** (default, scheme `sign-in`): any user who can sign in to the shared database — Windows integrated, SQL login (user + password) or Entra ID — opens the vault without a passphrase, whatever the app sign-in (Windows, Entra ID or none, FR-44). An existing vault can be converted to another protection once, on request, keeping its key ([ADR-0016](../adr/0016-sign-in-vault-key-protection.md), [ADR-0018](../adr/0018-database-sign-in-opens-vault.md)). |
| FR-29 | In remote mode entries can be kept on **this PC only**: they live in the local vault file of local mode (FR-20, own key bound to the Windows user and machine) and are never written to the shared database. The entry editor asks for a new entry whether it goes to the **Shared database** (default) or **This PC only**; while the shared database is offline new entries are kept on this PC. Local-only entries show a PC mark in the tree and "This PC only" in the details pane, can be edited and deleted also while offline, and publish no presence (FR-30). **Move to this PC only…** and **Move to shared database…** (details pane More menu, tree context menu; online only; Cancel is the default, FR-53) move an entry with its accounts and passwords: it is copied under new ids with its passwords re-encrypted for the target vault, then deleted from the source (a tombstone, FR-23); if the delete fails the copy is withdrawn. Pins and recent entries follow it. If the local vault cannot be opened, only local-only entries are unavailable. See [ADR-0038](../adr/0038-local-only-entries-in-shared-mode.md). |
| FR-27 | The shared database is configured with simple fields — server (name or IP), database name, database sign-in (Windows, SQL login with user + password, Entra ID), encryption options — with an option to create the database if it does not exist ([ADR-0014](../adr/0014-database-connection-form.md)). A raw connection string can still be edited; strings the fields cannot describe are kept as text. |

### 3.4 Session presence ("who is connected")

| ID | Requirement |
|---|---|
| FR-30 | When a user launches an entry and the shared database is reachable, the app writes a presence record: entry, the account connected as (FR-09), Windows/Entra user name, display name, e-mail, machine name, start time. |
| FR-31 | Each record has an expiry (default TTL 120 s). While the RDP client runs, the app refreshes it (default every 45 s). All times use the database clock. |
| FR-32 | Clients list only non-expired records. A record whose app crashed, lost network or was killed disappears from everyone's view after at most one TTL. |
| FR-33 | Entries with active sessions show an in-use marker in the tree — a dot and the user's name (or "N users"), its accessible name "In use by …" — and details (name, e-mail, machine, account, since); account rows (FR-09) show the marker for sessions using that account. Connecting asks for confirmation when a session uses the same account — or a record names no account (older clients) or the connection has no user name — because that would take the session over; sessions with other accounts do not block, as the host can run them side by side. |
| FR-34 | When the RDP client window closes, the record is deleted. Closing the app ends its records (after confirmation if sessions are still open). |
| FR-35 | If the database is unreachable at launch, the session still starts; presence is published as soon as the database is back. |
| FR-36 | Expired records older than one day are purged opportunistically. |

### 3.5 Identity

| ID | Requirement |
|---|---|
| FR-40 | Default sign-in uses the current Windows account without a prompt (domain or local). E-mail and display name come from Active Directory when reachable, otherwise from the UPN. |
| FR-41 | Optional Microsoft Entra ID sign-in via the Windows account broker (WAM): silent SSO on Entra/hybrid-joined devices, interactive otherwise. |
| FR-44 | Optional **no sign-in** mode: the user enters a name (required), used for presence and audit and shown as "(not signed in)". It is unverified, so Windows or Entra ID sign-in stays the default and recommended ([ADR-0015](../adr/0015-anonymous-named-mode.md)). |
| FR-45 | The Settings dialog is split into tabs, listed in a side navigation — **Storage** (local vault or shared database, chosen as two cards, and the connection), **Shared vault** (vault key protection, schema, sync and presence timings; disabled with a hint while local storage is chosen), **Sign-in**, **Remote Desktop**, **Appearance** (theme, FR-08) and **About** (version, links to the GitHub repository and the documentation, data folder with an Open button) — so no tab needs a long scroll. Below the connection fields a read-only preview shows the connection string they produce, with the password masked; the Test connection result is shown green (OK) or red (failed). <kbd>Ctrl+S</kbd> saves, <kbd>Esc</kbd> cancels; Save asks to restart only when something besides the theme changed. Related short fields share a row (server + database name, user name + password, encrypt + trust server certificate, client ID + tenant), short values get narrow boxes, and every tab keeps a gutter so its scroll bar never covers an input. Validation errors show below the tabs, whatever tab is open. See [ADR-0023](../adr/0023-tabbed-settings-dialog.md), [ADR-0027](../adr/0027-side-navigation-dialogs.md). |
| FR-46 | The entry editor is split into tabs, listed in a side navigation — **General** (type, name + folder, host + port, domain + user name, password, notes), **Accounts** (additional accounts, FR-09), and for RDP connections only **Display**, **Local resources** and **Connection** (the RDP settings form and "Other .rdp settings", FR-13) — so no tab needs a long scroll. Related short fields share a row, each additional account fits on one row (domain, user name, password, Remove), and every tab keeps a gutter so its scroll bar never covers an input. Validation errors show below the tabs, whatever tab is open; a failed save also opens the tab with the problem and puts the cursor in the field. The type is a two-way switch; host, port, domain, user name and folder use the monospace font. A stored password shows as "Stored, encrypted" with **Replace…** and **Remove** (and **Keep stored password** to undo), instead of a "change" checkbox; accounts likewise. On save, `host:port` typed in Host is split into Host and Port (when Port is still 3389 or the same), and `DOMAIN\user` typed in User name into Domain and User name (when Domain is empty). <kbd>Ctrl+S</kbd> saves, <kbd>Esc</kbd> cancels. See [ADR-0024](../adr/0024-tabbed-entry-editor.md), [ADR-0027](../adr/0027-side-navigation-dialogs.md). |
| FR-42 | The signed-in identity is used for presence (FR-30) and audit (`UpdatedBy` on entries). |
| FR-43 | Access to the shared SQL database uses the connection string's authentication: Windows integrated, SQL Server login, or Entra ID (`Authentication=Active Directory …`). It is independent of the app sign-in (FR-40/41): every sign-in works with both storage modes. |

### 3.6 File transfer

| ID | Requirement |
|---|---|
| FR-60 | **Transfer files…** (details pane More menu, tree context menu, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>T</kbd>) opens one non-modal File transfer window for the selected entry with a host and its selected account (FR-09). With **Copy over: Network share (port 445)** (FR-63 is the other way), files are copied over SMB to or from a folder on the host given as a UNC path — default `\\<host>\C$\Users\Public\Downloads`, editable, the last one remembered (`TransferRemoteFolder`). Before every attempt the share is connected with the account's user name and password (Windows API, never a command line or file, NFR-12), or as the signed-in Windows user when the entry has no user name. **Upload files…** and **Upload folder…** (with its sub-folders) copy to the host; **Download…** opens the remote folder to pick files and then a local folder. Files that already exist are handled as chosen in FR-64; an existing local file is replaced only after a confirmation. The list shows each file's direction, destination, progress and state with **Pause**, **Resume** and **Cancel** (deletes the partly copied file), plus **Resume all** and **Clear done**. See [ADR-0039](../adr/0039-resumable-file-transfer.md). |
| FR-61 | Transfers **survive dropped connections**: each file is copied in chunks (1 MiB; a journal keeps the size it started with, ADR-0042) to `<name>.harbor-part`, and after every flushed chunk its position and hash are saved in a journal (`transfers\<id>.json` in the data folder), so the app always knows where the copy stopped. A connection problem is retried automatically (waits growing to 30 s) from the last saved chunk; after 10 minutes without progress the transfer pauses and can be resumed. Before resuming, the partial file is checked against the journal (length and last chunk's hash) and a changed source starts over; when complete the file gets its final name. Transfers unfinished when the app closed (or crashed) come back paused and resume where they stopped; closing the app with unfinished transfers asks first (Cancel is the default). The journal holds no secret. See [ADR-0039](../adr/0039-resumable-file-transfer.md). |
| FR-63 | File transfer can go **through the Remote Desktop connection** (**Copy over: Remote Desktop (port 3389)**, the default; **Network share (port 445)** is FR-60), for networks where only the Remote Desktop port is open. The folder is given as the server sees it (default `%USERPROFILE%\Downloads`, remembered as `TransferServerFolder`; the method as `TransferMethod`), with files that already exist handled as chosen in FR-64. Upload files…, Upload folder… or Download… (local target folder; the files are picked in a dialog in the session) writes a plan and a copy helper into `rdp-transfers` in the data folder, connects the entry (FR-10) with the needed drives of this PC and the data folder's drive shared into the session for this launch only (`drivestoredirect`, merged with the entry's own), and puts a start command (`\\tsclient\<drive>\…\start.cmd`) on the clipboard; the window says to press Win+R, Ctrl+V and Enter in the session and offers **Copy command**. The helper (Windows PowerShell, nothing installed) copies in chunks like FR-61 and keeps its journal on the server, so it survives a dropped connection: it waits for Remote Desktop to reconnect and continues where it stopped; running the start command again also resumes. Its progress (file n of m, bytes, waiting, done, failed) shows in the transfer list; **Cancel** asks it to stop and delete partial files. No password is written to any file or command line (NFR-12). See [ADR-0041](../adr/0041-file-transfer-through-remote-desktop.md). |
| FR-64 | The File transfer window asks what to do with **files that already exist** at the destination, for both ways of copying (FR-60, FR-63): **Fail** (the default; that file fails, the others are copied), **Skip** (only files not there yet are copied: a file with the same name and extension in the same sub-folder is left as it is and its row says *Skipped*; a Remote Desktop transfer counts the skipped files) or **Replace** (a local file only after a confirmation; declining skips them). The choice is remembered (`TransferExistingFiles`). **Upload folder…** copies the folder with all its files and the files of all its sub-folders, so Skip applies at every level. A skipped file is never opened or changed and no partial file is left for it. |
| FR-65 | Remote Desktop transfers (FR-63) **start by themselves** in **Harbor's transfer window**, so nothing has to be typed in the session (**Start the copy for me**, on by default, remembered as `TransferAutoStart`; disabled when the Remote Desktop ActiveX control of Windows is missing). Instead of `mstsc.exe`, the transfer connects in a window of the app that hosts the Remote Desktop control (an exception to FR-10, for transfers only): host, port, account and password of the entry (the password handed to the control in memory only, NFR-12), its authentication level and administrative session, every drive of this PC and the clipboard shared, its own window size; the takeover and production questions and presence of FR-10/FR-33 apply. Entries that go through a Remote Desktop Gateway connect with mstsc as in FR-63. Once signed in (and a few seconds for the desktop), the window puts the start command with `/auto` on the clipboard and types Win+R, Ctrl+V and Enter into the session — only while it is the window in front, so nothing is typed into another program; otherwise, or when keys cannot be sent, its **Start copy** button does it and Win+R, Ctrl+V, Enter by hand still works. It does not start the helper again for a transfer that is done or cancelled, and the helper itself refuses to run twice for one transfer. With `/auto` the helper's console closes when it ends. The transfer list shows the window's state until the helper reports; **Show window** / **Connect** on a transfer brings the window to the front or connects again (the copy continues, or starts again where it stopped); **Reconnect** in the window does the same after a dropped connection. The window is closed (disconnected; the session stays) as soon as the copy is done or cancelled, so the PC's drives are shared only while needed. See [ADR-0042](../adr/0042-transfer-window-starts-the-copy.md). |

## 4. Non-functional requirements

| ID | Requirement |
|---|---|
| NFR-01 | **Performance first.** Main window visible in < 1 s on typical hardware; catalog shown from the local SQLite file before any network call; sign-in, sync and presence never block the UI thread. |
| NFR-02 | Runs **without administrator rights** and **without installation**: a single self-contained `RemoteDesktopHarbor.exe`; per-user data; manifest `asInvoker`. |
| NFR-03 | Smooth with 10 000 entries (UI virtualization, in-memory filtering). |
| NFR-04 | Default CI and release target: **Windows x64**. |
| NFR-05 | Must stay publishable to the **Microsoft Store** (MSIX) later without architectural changes. |
| NFR-06 | *Withdrawn* — release exes are not code-signed for now (ADR-0037; was: signing through SignPath Foundation, ADR-0036). |
| NFR-10 | Secrets are encrypted with AES-256-GCM. Local keys are bound to the **Windows user and the machine** (DPAPI); a copied database cannot be decrypted elsewhere. |
| NFR-11 | Ciphertexts are bound to their entry (associated data); swapped or tampered ciphertexts fail to decrypt. |
| NFR-12 | No plaintext secret on disk, in `.rdp` files, on command lines or in logs. |
| NFR-13 | With AD-group or passphrase protection, a database administrator of the shared database without vault access sees only ciphertext. With sign-in protection (FR-28) database access is vault access — an accepted trade-off chosen in Settings. |
| NFR-20 | SQL engine specifics are isolated in one provider class per engine. |
| NFR-30 | Business logic, storage and crypto are covered by automated tests that run in CI on any OS. View-model tests that need WPF or DPAPI (`Harbor.App.Tests`) run on Windows only (CI). |

## 5. Data model

All timestamps are Unix milliseconds (UTC) from the database clock. Ids are GUID strings.

| Table | Columns | Notes |
|---|---|---|
| `Connections` | Id, Name, Folder, Kind (0 RDP, 1 credentials only, 2 other), Host, Port, Domain, UserName, RdpSettings, Notes, PasswordCipher, Version, CreatedUtcMs, UpdatedUtcMs, UpdatedBy, IsDeleted | `Version` = optimistic concurrency token; deletes are tombstones so caches learn about them. |
| `ConnectionAccounts` | Id, ConnectionId, Position, Domain, UserName, PasswordCipher | Additional accounts of an entry (FR-09), written with the entry in one transaction; the entry's `Version` covers them. Removed when the entry is deleted. |
| `ActiveSessions` | Id, ConnectionId, UserName, DisplayName, Email, MachineName, StartedUtcMs, LastHeartbeatUtcMs, ExpiresUtcMs, AccountName | Presence (FR-30..36). Only used in the shared DB. `AccountName` is the remote account (FR-09); null from older clients. |
| `VaultKeys` | Slot, KeyId, Scheme, ProtectedKey, CreatedUtcMs | Wrapped data-encryption key. `Scheme` names the protector. |
| `Meta` | Key, Value | e.g. sync watermark in the cache. |

Entries kept on this PC only (FR-29) are rows of the local vault file with the same schema; which store an entry came
from is not a column. File transfers (FR-61) are journaled as JSON files, not in a database.
| `SchemaVersion` | Version | Applied migrations. |

## 6. Security model

```
                      ┌──────────────── shared SQL DB ────────────────┐
 password ─AES-GCM──► │ PasswordCipher (DEK)   VaultKeys: DEK wrapped │
                      │                        with DPAPI-NG (AD group)│
                      │                        or passphrase           │
                      └───────────────────────────┬───────────────────┘
                                                  │ sync (ciphertext only)
                      ┌──────────── local SQLite (cache / vault) ─────┐
                      │ PasswordCipher (same DEK)  VaultKeys: DEK      │
                      │                            wrapped with DPAPI  │
                      │                            user + machine      │
                      └───────────────────────────────────────────────┘
```

* **Envelope encryption** ([ADR-0005](../adr/0005-secret-encryption-envelope.md)): one random 256-bit data-encryption
  key (DEK) per vault encrypts all passwords (AES-256-GCM, entry id as associated data).
* **Local binding:** the DEK in any local SQLite file is wrapped with DPAPI *CurrentUser* and then *LocalMachine*:
  only this Windows user on this computer can unwrap it.
* **Shared binding** ([ADR-0006](../adr/0006-shared-vault-key-protection.md), [ADR-0016](../adr/0016-sign-in-vault-key-protection.md)):
  by default the DEK is stored **unencrypted** in the shared DB (scheme `sign-in`, shown as *Not protected*; no
  passphrase; anyone who can read the database or a backup can open it, including a DBA, ADR-0018). Alternatively in the shared DB the DEK is wrapped with
  DPAPI-NG to an AD security group (recommended) or with a passphrase-derived key (PBKDF2-SHA256, 600k iterations).
  After the first successful unwrap, each client caches the DEK locally (DPAPI user + machine) so offline mode works.
* **Threats addressed:** stolen laptop disk/DB copy (DPAPI binding), DB admin reading passwords (ciphertext only — when the shared DEK is wrapped with DPAPI-NG or a passphrase,
  not with the default *Not protected*),
  row tampering (GCM + AAD), password leakage via process list/.rdp files (Credential Manager hand-off).
* **Out of scope / accepted:** a user who can unwrap the vault can read every password in it (that is the purpose
  of a shared vault); malware running as the same Windows user; key rotation (future work).

## 7. Settings

Stored as JSON in the data folder (`%LOCALAPPDATA%\RemoteDesktopHarbor\settings.json`, or `.\data` in portable mode).
The remote connection string — including a SQL login password, if used — is DPAPI-protected. See `HarborSettings`
for the full list.
